### 3. The citation debt (the September risk)

**P-07, P-08 and P-10 through P-22 are unverified.** P-01..P-06 and now P-09 have been
checked. Appendix B sources 166-178 were never click-checked. This is the thing that
gets a manuscript declined by an acquisitions editor, and it is the largest open job
in the book.

- [x] **P-09's Wellington comparison. VERIFIED AND CUT, 2026-07-26.** The probe came
      back positive: the claim is false. Chapter 7 said twelve thousand anti-Luddite
      troops was "more than Wellington had just taken to fight Napoleon in the
      Peninsula." Provenance traced: **Frank Darvall (1934, p.260) never named
      Wellington** — he wrote only that the force was larger than many armies with
      which British generals had won foreign campaigns. **Eric Hobsbawm added the
      Wellington comparison** in "The Machine Breakers" (*Labouring Men*), and it has
      been repeated ever since. It fails on the numbers: Britain committed roughly
      **43,000** troops to the Peninsula during 1808 (Wellesley's 9,000, 6,000 in
      reinforcements, Baird's 13,000 and Moore's 15,000 in October), and by **1812**,
      the year the Frame Breaking Act passed and the risings peaked, roughly **50,000**
      were there, rising to 73,000 by October 1813. Only "Wellesley sailed from Cork
      with 11,000" makes it work, and that is cherry-picking. It fails qualitatively
      too: the anti-Luddite force was largely militia and yeomanry, not regulars
      available for overseas service.

      **Ruled by the book's own standard, not by judgment.** Appendix D's "Sourcing"
      note says claims that cannot survive a primary source are *cut, not softened* —
      it is the same species as the Western Union "telephone is a toy" memo the book
      brags about excluding, sitting two appendices from the note disclaiming it.
      So the comparison was removed rather than hedged. The twelve thousand figure
      itself is Darvall's and **stands**; only the comparison attached to it was wrong.

      Replaced with verified specifics that do more rhetorical work anyway: at the York
      Special Commission, 64 were charged and 24 convicted; **three men hanged 8 January
      1813** (Mellor, Thorpe, Smith, for the murder of William Horsfall) and **fourteen
      more on 16 January in two groups of seven**, at 11:00 and 13:30. Corroborated
      across two independent sources. The old line "Men were hanged at York in batches"
      was checked too and turned out to be literally true.

      Appendix B gains **`## P-09 Primary Sources` (187-192)**, following the pattern the
      P-01 and P-02 blocks already set, headed by an italic correction of record so a
      future draft cannot silently reintroduce the comparison. Source 143 (a bare
      Wikipedia link) was carrying this entire case file on its own, which is *why* the
      error survived.

      **The diagnostic read: the failure mode is inheritance, not invention.** The book
      does not fabricate. It absorbed a vivid secondary-source claim with its error
      intact, and the citation behind it was too thin to catch it. So the audit of the
      remaining fifteen precedents should hunt **comparison claims** ("more than X",
      "larger than Y", "the first Z") rather than fabricated quotes, and should treat
      any precedent whose only citation is a bare Wikipedia link as unverified by
      default.

## Working rules

**The version is already bumped.** `book.json` reads `0.7.3` as of this document, so
content edits land in an open version rather than triggering a bump each time. Do not
bump again inside this cycle.

**Do not run the build ritual per change.** EPUB, PDF variants, and the
`static/downloads/` swap happen once, at close, run by the synthesizer. See
`AUDITOR-BRIEF.md` section 5.

**Do not merge to main.** Main auto-deploys production and production runs live
Stripe keys. Merging is CT's call.

**Run the harness at both ends of any pass:**

```bash
python3 scripts/sts.py verify          # math, meta, precedents. Exits non-zero.
python3 scripts/sts.py verify --links  # add the network source check
python3 scripts/sts.py book            # current word counts. Trust this over any doc.
python3 scripts/sts.py id verify       # block index integrity after manual .md edits
```

A doc that asserts a version or a word count is a claim, not a measurement. Only
`book.json` and `sts.py` are authoritative. `AUDITOR-BRIEF.md` currently carries 15
stale version strings, which is exactly the failure that let a live pricing bug sit
unnoticed for ten days.

**`id verify` cannot catch a stale index. Found 2026-07-26, verified two ways.**
`_id_verify` (`scripts/sts.py:1945`) calls `_live_index()` (`:1768`), which **rebuilds
the index from the .md files on disk** and uses the persisted `manuscript-index.json`
only for id continuity — its own docstring says so. `_verify_index` (`:1898`) then
recomputes each block hash from those same files and compares. So **`hash.match` and
`span.valid` compare disk against disk**: they are tautologies that can only fail if
the parser disagrees with itself. Demonstrated, not merely read: the persisted index
was hand-set to hash `1980fdca0aed` for `sts.introduction.b0006` while line 13 of
`02-introduction.md` hashes to `f5b19d93fc8a`, and `id verify` still printed
`PASS hash.match []`.

Consequence: the warning below about committing an index that describes an uncommitted
file is real, but **nothing in the harness enforces it.** The only actual check is
reading `git diff src/lib/data/book/manuscript-index.json` yourself and confirming it
touches only the sections you edited. `id.unique`, `coverage.exact` and `art.links`
are unaffected and still mean what they say — `art.links` still catches a figure
orphaned by a restructure, because it resolves against `art-catalog.json`.

**This happened during this pass.** `id build` absorbed a concurrent session's
uncommitted edit to `02-introduction.md`; the block was hand-reverted to its HEAD
values (`words` 74, `hash` `1980fdca0aed`, section 2105, totals 88941) so the index
describes committed content. The persisted index therefore disagrees with the working
tree on that one block until the other session lands its edit. That is intended.
