/call-it v0.0.1 2026-08-01 · 17:28 PDT
New command

/call-it

You have options. You do not need more options. This command reads the current state and tells you the one thing to do next, in my opinion, with the alternatives I rejected and a forecast you can hold me to.

SolvesThe menu problem. Five ranked options is a way of not being wrong, not a way of being useful.
ReturnsSeven blocks, under 250 words, one screen. Never a menu.
RefusesTo recommend anything whose premise it did not verify this turn.
StatusInstalled and live at ~/.claude/skills/call-it/SKILL.md
01 · Why

The menu is a hedge

When I hand you five ranked options with trade-offs, I have moved zero decisions. The work of choosing is still yours, and I have protected myself from being wrong. This command removes that escape hatch.

02 · Output contract

Seven blocks, always the same

Predictable shape means you can scan it in ten seconds and know where to look.

THE CALL
One imperative sentence. No "consider", no "you might". If I will not phrase it as an instruction, I have not made a call.
CONFIDENCE
High, medium or low, plus what would raise it. All hedging lives here and nowhere else.
WHY NOW
Two or three lines, tied to something measured this turn. Not something I remember from earlier.
COST
Minutes, dollars, and how hard it is to undo.
IF YOU SKIP IT
The concrete consequence, and who finds out first. Often a customer. That is the point.
RUNNERS-UP
Two or three rejected options, each with one line on why it lost, so you can overrule me intelligently.
PROGNOSIS
Where you stand in 1 hour, 1 day, 1 week. Concrete enough to be wrong.
03 · Live demo

Run against your actual state, right now

Not a mock-up. I re-probed production at 17:28 PDT before writing this, because the command's first rule is that an opinion about stale state is a guess with confidence attached.

sts-v0.7.3 — /call-it
› /call-it
THE CALL
Run the two read-only SQL queries against live Supabase. Before anything else.
CONFIDENCE
High. Raised further only by the query results themselves, which take about thirty seconds.
WHY NOW
Re-probed 17:28 PDT: production is still mode test. The webhook writes a financial ledger that fails closed by design, so if checkout_transactions was never created, every paid order returns 500. That single unknown decides whether today is a launch day or a migration day, and everything else in the runbook is wasted effort until it is answered.
COST
Thirty seconds. Zero dollars. Read-only, so fully reversible by definition.
IF YOU SKIP IT
You go live, a customer pays $5, Stripe retries for three days, and they receive nothing. You find out from them, not from your monitoring.
RUNNERS-UP
Register the live webhook. Correct next step, but pointless if the ledger table is missing.
Install webkit, clear 304 test failures. Satisfying, cosmetic, blocks no money.
Stop for today. Genuinely on the table, but the blocker is thirty seconds of work and you are at the dashboards.
04 · Prognosis

Concrete enough to be wrong

1 hour

You know whether the schema supports the pipeline. If yes, live keys are in and sts.py stripe --live reads mode live. If no, you are running one migration instead of debugging a live outage.

1 day

One real $5 purchase has delivered an email, an admin alert, and a cs_live_ row. That is the first end-to-end proof this pipeline has ever had.

1 week

Marketing runs against a till that works. The daily guard alarms on real drift. The v0.7.3 merge happens on a calm day instead of a launch day.

Stop condition. If query one returns checkout_transactions and query two shows all four durability columns, this call is spent. The next call becomes the live webhook.

05 · When to reach for it

Three commands, three jobs

CommandAnswersOutputReach for it when

/handoff How does the next session resume? Copy-paste prompt Context is running out or you are switching chats
06 · Rules that keep it honest

The constraints are the feature

  • One call. Two co-equal options is a failure of the command, not a nuance.
  • Startable in 30 minutes. Anything bigger is a project. It gets decomposed and the first step gets called.
  • "Stop for now" is a valid call. Fatigue and bad deploy windows are real. No manufactured urgency to seem useful.
  • Blocked on you is still a call. I say exactly what I will do the second you unblock it, so the handoff is clean.
  • Rejected options get named. A recommendation with no alternatives is indistinguishable from a guess.
  • Values decisions stay yours. Pricing, naming, whether to launch at all. I lay out the trade and stop. Making a call on someone else's values is overreach, not confidence.
  • No recommending the fun work over the unblocking work. When those diverge I notice it out loud.
