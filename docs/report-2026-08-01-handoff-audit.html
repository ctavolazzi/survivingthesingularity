What changed, part one

The handoff was audited instead of believed

The continuation prompt contained an instruction aimed at itself: do not trust any summary of state, including this one, without re-measuring. That instruction paid for itself. Eleven checkable claims went in. Seven came back true, two came back false, and two had drifted since writing.

Fig 1. The handoff's own self-distrust clause, executed literally.

The two refutations share a cause. The handoff was written by a session that believed it had pushed nothing, and it wrote that belief down as a fact about three repos at once. Two of the three were already fully synchronised with their remotes. Had I acted on the sentence rather than checked it, I would have opened push conversations about work that was already on GitHub.

The cheap check that settles it. Ahead-count against a stale remote-tracking ref reads zero for a repo that has never fetched, and reads zero for a repo that is genuinely in sync. Those are different states with the same number. Comparing git ls-remote against local HEAD distinguishes them without trusting any local cache. Both repos returned identical SHAs.

Why the positive control matters

It proves the measurement path reaches real state. A checker wired to the wrong repo, the wrong branch or a stale ref can return plausible-looking numbers forever. The 19/5 row came back matching a figure written by a different session on a different day, which is only possible if both were reading the same thing.

Why the negative control matters

It proves the pass can say no. Nine confirmations in a row is exactly what a rubber stamp looks like. The _pyrite row is the evidence that this table was capable of contradicting the document it was auditing, and did.

One row deserves suspicion even now. The sts.py factcheck numbers still read network: OFF, 776 UNCHECKED, because that verb reports the committed docs/factcheck-2026-07-30.json snapshot. The other session's network results are in the cache and in its commit message, not yet in the published JSON. Do not read 776 as the current state of the audit. Read it as the state of the last published artifact.

The moving part

Two writers, one worktree

Drag to orbit. The blue node is the concurrent session, and its work reaches the shared HEAD spine. The grey node is this session: it observes, it backs up off to the side, and it lands nothing. Both are attached to the same trunk, and that is the whole problem.

The trunk is shared mutable state

One filesystem, one index, one HEAD. Git gives no isolation between two processes in the same checkout. There is no lock that makes a second writer wait, and no warning that one exists.

The particles that stop short

They are the commits I did not make. The two files I was told to protect were protected by the other agent 74 seconds apart while I was reading a diff. Duplicated effort here was harmless. It is not always harmless.

Where it stops being harmless

The factcheck run writes one cache directory and one output JSON, over hundreds of rate-limited network fetches. Two resumable jobs sharing a resume file do not merge. They interleave, and the corruption is silent.

What changed, part two

How the second session was caught

Not by looking for it. By re-running a command I had already run, for an unrelated reason, and noticing the answer had changed.

Fig 2. The detection was incidental. Nothing was watching for a second writer.

The sequence that exposed it: I ran git log to copy the repo's commit message style before writing my own. The top entry was a commit that already did what I was about to do. My first instinct was that I had misread my own earlier git status. Re-running it settled the question in the other direction, and the second commit landed 37 seconds after the first.

The generalisable part. A measurement taken at the start of a session is an assertion about a moment, not about the session. In a repo that another process can write to, the gap between measuring and acting is the window where the measurement expires. Re-measure immediately before the write, not only at the plan.
